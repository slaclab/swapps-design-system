# Application layouts

## Standard layout

Most SWAPPS applications follow a common structure:

1. **Application header** — Organization branding, application title, and top-level navigation.
2. **Optional side navigation** — For applications with many sections.
3. **Main content area** — The primary workspace.
4. **Optional footer** — Status information or secondary links.

```
┌────────────────────────────────────────┐
│  AppHeader (org name · app title · nav)│
├──────────┬─────────────────────────────┤
│ Side Nav │                             │
│          │    Main Content Area        │
│  - Link  │                             │
│  - Link  │                             │
│  - Link  │                             │
│          │                             │
├──────────┴─────────────────────────────┤
│  Footer (optional)                     │
└────────────────────────────────────────┘
```

## Header-only layout

For simpler applications, the side navigation can be omitted. Navigation lives in the header bar.

```
┌────────────────────────────────────────┐
│  AppHeader (org name · app title · nav)│
├────────────────────────────────────────┤
│                                        │
│         Main Content Area              │
│                                        │
└────────────────────────────────────────┘
```

## Guidance

- Use Carbon's `Content` component for the main content area — it handles spacing around the header.
- Keep navigation predictable. Users should always know where they are.
- On smaller screens, side navigation should collapse or become a hamburger menu.

A combined `AppShell` component that assembles these layouts from configuration is planned. See [Application Shell](/docs/components/app-shell).
