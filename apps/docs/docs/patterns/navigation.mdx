# Navigation

SWAPPS applications handle navigation with two complementary tools: the [AppHeader](/docs/components/general-ui/app-header) for top-level navigation, and Carbon's [`SideNav`](https://react.carbondesignsystem.com/?path=/story/components-ui-shell--header-base-w-side-nav) for side navigation. No additional wrapper is needed — these components cover the full range of navigation patterns.

## Top navigation

Use the [AppHeader](/docs/components/general-ui/app-header) for primary navigation when the application has a small number of top-level sections (roughly 2–7 items). The AppHeader handles organization branding, application title, and nav items in a single component.

## Side navigation

Use Carbon's `SideNav` for applications with many sections or deep hierarchies. Side navigation is persistent and gives users a clear overview of available sections.

Applications with three or more top-level sections (e.g. Save, Compare, Restore) often benefit from a sidebar for primary navigation rather than cramming everything into the header.

```tsx
import { SideNav, SideNavItems, SideNavLink } from '@carbon/react';

<SideNav aria-label="Side navigation">
  <SideNavItems>
    <SideNavLink href="/dashboard">Dashboard</SideNavLink>
    <SideNavLink href="/experiments">Experiments</SideNavLink>
  </SideNavItems>
</SideNav>
```

## Sidebar for filters

A sidebar is especially useful for housing filters. When an application relies heavily on filtering — searching through log entries, narrowing down datasets, or scoping results — placing filters in a collapsible sidebar keeps them accessible without consuming the main content area.

**Why sidebar over top bar for filters?**

- **Vertical space** — Filters often have many options (date ranges, dropdowns, checkboxes). A sidebar gives them room to grow without crowding the header or pushing content down.
- **Collapsibility** — Users can collapse the filter sidebar when they want to focus on results, then expand it when they need to refine. This is especially valuable on smaller screens.
- **Scanability** — A vertical list of filters is easier to scan than a horizontal row, particularly when there are more than 3–4 filter controls.

For applications with a small number of filters (1–3 simple controls), a top bar or inline filter row above the content may be sufficient.

## Combined

Applications can combine top navigation (for primary sections) with side navigation (for subsections or filters within each section). See [Application Shell](/docs/components/general-ui/app-shell) for layout diagrams showing how these combine in real applications.

## Guidance

- Keep top-level navigation items to 7 or fewer.
- Use clear, concise labels.
- Indicate the active section visually.
- Ensure navigation is keyboard-accessible.
- On mobile, collapse navigation behind a menu button.
- For filter-heavy applications, prefer a sidebar over a top bar for filter controls.
- Make filter sidebars collapsible so users can maximize content space when not actively filtering.
