# Adoption guide

This guide is for teams considering adopting the SWAPPS Design System for their applications.

## Who can use this?

The SWAPPS Design System is built and maintained by the SWAPPS team at SLAC National Accelerator Laboratory. However, it is designed so that **any software development team** — at SLAC or at other laboratories — can adopt the shared components and guidelines.

## What you get

- **Consistent UI patterns** — Headers, navigation, layouts, and application shells that look and behave the same across applications.
- **Accessible by default** — Components follow IBM Carbon's accessibility conventions, including keyboard navigation, ARIA labels, and screen reader support.
- **Configurable branding** — Customize organization name, logo, and application title without modifying shared code.
- **Documentation** — This site serves as the central reference for design guidelines and component APIs.

## Adoption path

### 1. Evaluate

Browse the [foundations](/docs/foundations/design-principles), [components](/docs/components/overview), and [patterns](/docs/patterns/application-layouts) to understand what the system provides.

### 2. Install

Follow the [installation guide](/docs/getting-started/installation) to add the library to your project.

### 3. Configure

Set up your organization's branding using component props and theme configuration. See [themes](/docs/themes/overview).

### 4. Build

Use the shared components alongside Carbon's UI primitives to build your application.

### 5. Contribute

Found a bug or have a suggestion? See the [contributing guide](/docs/getting-started/contributing).

## What this system does _not_ provide

- **SLAC-specific branding** — Organization identity is configured per-application, not baked into shared components.
- **Every UI component** — For buttons, inputs, tables, and other primitives, use [IBM Carbon](https://carbondesignsystem.com/) directly.
- **Design files** — Figma assets are managed separately. See [resources](/docs/resources/roadmap).
