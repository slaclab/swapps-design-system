# Light and Dark Mode

## Approach

The SWAPPS Design System supports both light and dark color schemes through IBM Carbon's theme system. Appearance is shared across all component categories — general UI, scientific controls, and charts all respond to the same light/dark setting.

Appearance is independent of organization branding. Any laboratory's theme works in both modes.

## Using SWAPPSThemeProvider

The recommended way to control appearance is through `SWAPPSThemeProvider`:

```tsx
import { SWAPPSThemeProvider } from '@swapps/ui';

// Light mode
<SWAPPSThemeProvider config={{ appearance: 'light', branding: { organizationName: '' } }}>
  {/* Components render with white/light backgrounds */}
</SWAPPSThemeProvider>

// Dark mode
<SWAPPSThemeProvider config={{ appearance: 'dark', branding: { organizationName: '' } }}>
  {/* Components render with dark backgrounds */}
</SWAPPSThemeProvider>
```

## Carbon theme mapping

| Appearance | Carbon theme | Description |
|---|---|---|
| `'light'` | `white` | Light backgrounds |
| `'dark'` | `g100` | High-contrast dark UI |

For raised surfaces (panels, cards), use the `appearanceToCarbonTheme` utility with the `'raised'` variant:

```tsx
import { appearanceToCarbonTheme } from '@swapps/ui';

appearanceToCarbonTheme('light', 'raised');  // 'g10'
appearanceToCarbonTheme('dark', 'raised');   // 'g90'
```

## Using Carbon's Theme directly

You can also use Carbon's `Theme` component directly for scoped theme sections:

```tsx
import { Theme } from '@carbon/react';

<Theme theme="g100">
  {/* Dark mode content */}
</Theme>
```

This works independently of `SWAPPSThemeProvider` and is useful for embedding a different appearance in a specific section.

## Light/dark mode vs. branding

These are separate concerns that compose independently:

| Combination | Result |
|---|---|
| SLAC + Light | SLAC branding on light backgrounds |
| SLAC + Dark | SLAC branding on dark backgrounds |
| Fermilab + Light | Fermilab branding on light backgrounds |
| Fermilab + Dark | Fermilab branding on dark backgrounds |

The same component handles all combinations. Switching appearance does not affect branding, and vice versa.

## What adapts to appearance changes

| Element | Adapts | Source |
|---|---|---|
| Surface backgrounds | ✓ | Carbon tokens |
| Text colors | ✓ | Carbon tokens |
| Border colors | ✓ | Carbon tokens |
| Interactive states | ✓ | Carbon tokens |
| Status indicator colors | Partially | Semantic tokens (fixed values, but components may adjust presentation) |
| Chart backgrounds & axes | ✓ | Carbon tokens |
| Brand colors | No change | Configured by the application |
| Visualization palette | No change | Fixed for consistency |

## Guidance

- Use `SWAPPSThemeProvider` to set appearance at the application root.
- Use Carbon color tokens so elements adapt automatically.
- Test all components in both light and dark modes.
- Avoid hardcoding colors that don't respond to theme changes.
- Consider the `prefers-color-scheme` media query for respecting system preferences.
- In the documentation site, use the [Themes configurator](/docs/themes/overview) to preview components in both modes.
